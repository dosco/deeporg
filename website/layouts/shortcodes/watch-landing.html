How did it know nothing happened?It can watch for something not happening

You say how long is too long. A watch that sees no rows in four hours alerts you just as one that sees a thousand would, so a gap in the data does not go unnoticed.

Why did it send only one message?It filters the noise first

Routine events are dropped or gathered into one summary, and related watches are combined into a single alert. You got one message, not four.

What if the model gets it wrong?It can alert you, but it cannot act alone

An alert always gets through. If the AI step that sorts alerts is unavailable, DeepORG still sends you the plain notification. An action never runs unapproved. A workflow waits for the approval it needs, whatever else fails.

What it costs

Keeping a question running does not use a model.

An organization can afford hundreds of these questions because keeping one running involves no model. DeepORG compiles the question once, and after that the database answers it like any other query.

While it runsDatabase polls, not model calls

A watch polls the database. It picks up where it left off, compares the new result with the last one, and stays quiet when nothing changed. No model decides whether something happened.

When you create itOne agent session

Describe the question in plain words and the agent writes the query for it. That is the only time a model is used, so choosing a bigger model does not make the watch cost more to keep running.

When it finds somethingThe AI step is optional and capped

By default, when a watch finds something it puts the data in your inbox. You can turn on an AI step, watch by watch, that summarizes, scores or filters alerts. It has a daily cap, so a noisy source cannot run up a bill.
